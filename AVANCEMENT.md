## Décisions techniques prises (à ne pas redécider)

- `CsvHelper` épinglé en version `33.0.1` (voir le skill `tuteur-csharp-clubmailer` pour le détail du bug qui a motivé ce choix).
- Niveau de code visé : professionnel/idiomatique dès le départ, proportionné à la taille du projet (pas de sur-architecture).
- Un mail par inscription (une personne inscrite à deux courses reçoit deux mails).
- Mode de chiffrement SMTP : `StartTls` par défaut, modes non chiffrés refusés à la validation.
- Journaux : ne jamais journaliser l'objet Participant entier (il contient l'email) ; NomComplet pour l'instant, puis l'identifiant d'inscription (licence + course) au Module 10 (décision du 19/11/2026).
- Connexion SMTP initiale non réessayée (seule la reconnexion dans la boucle l'est) ; à revoir au Module 18.
- Logs (décision du 17/11/2026, option 1) : `ILogger` (Microsoft.Extensions.Logging) pour la console, avec modèles `{Nom}` et l'exception en premier argument ; `SendingErrorLog` reste ce qui écrit dans un fichier (`ILogger` n'a pas de fournisseur fichier intégré) et doit donc être appelé dans chaque `catch` d'erreur d'envoi ou de connexion. Au Module 18, Serilog branche le fichier sur `ILogger` et `SendingErrorLog` disparaît.
- Sécurité des envois (décision du 19/11/2026) : drapeau `Envoi:Mode` dans `appsettings.json`, énumération `ModeEnvoi` = `Simulation` (aucune connexion SMTP, on journalise ce qui serait envoyé) / `Test` (envoi seulement si `Smtp:Host` = `smtp.ethereal.email`, sinon refus de démarrer) / `Reel` (avertissement + confirmation tapée au clavier). Défaut si absent : `Simulation`. Mode et Host journalisés au démarrage. Claude ne lance le programme qu'en `Simulation` ou en `Test` vers Ethereal (règle dans le skill et dans `CLAUDE.md`).
- Lecture du vrai export (décision du 19/11/2026, Module 9) : l'application doit accepter les deux formats, mêmes 30 colonnes. (A) export direct de la plateforme : `;`, UTF-8 avec BOM, LF, 51 champs par ligne de données (21 vides), ligne vide entre les blocs. (B) fichier ré-enregistré depuis Excel : tabulation, Windows-1252 sans BOM, CRLF, 30 champs, ligne de 29 tabulations entre les blocs. Détection automatique (encodage + séparateur), vérification des colonnes attendues, refus d'un format inconnu avec message clair, format détecté journalisé.
- Tests (décision du 20/11/2026) : les tests commencent au Module 9 ter (xUnit v3, projet `tests/ClubMailer.Tests`), juste après la CI du Module 9 bis et avant la refonte du Module 10, puis chaque module ajoute ses tests ; le Module 16 devient « Qualité et automatisation ». Pourquoi : avoir un filet de sécurité avant les gros changements. Revu au : Module 16.
- CI/CD (décisions du 20/11 et du 23/11/2026) : Module 9 bis (juste après le Module 9) = CI qui compile ClubMailer à chaque push, faite en parallèle sur GitHub Actions (`.github/workflows/ci.yml`) ET GitLab CI/CD (`.gitlab-ci.yml`) ; tout est doublé à chaque fois, et un module n'est fini que si les deux pipelines sont verts. GitHub reste le dépôt principal (`github.com/ken-oh91/ClubMailer_CSharp`) ; un seul `git push` envoie aux deux. Les fichiers de CI s'enrichissent à chaque module ; la partie CD (release du `.exe`) arrive au Module 17. Dépôt public visé, après vérification (aucun vrai CSV ni secret dans l'historique). Revu au : Module 17.
